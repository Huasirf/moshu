## 2. 两种形态

### 方案 A：绿色便携 ZIP（推荐）

应用目录 + 项目目录 + 文档打成一个 ZIP，解压即用，不写注册表、不需要管理员权限。

- 适合：自己换电脑、换工作环境、给合作者一份完整可运行的环境。
- 优点：路径可控、可回滚、可整包备份；应用和书在一起，不会出现“装了应用找不到项目”。
- 缺点：首次运行 SmartScreen 会提示（未签名）；不能自动更新。

### 方案 B：NSIS 安装包 + 项目数据包

`electron-builder` 已配置 NSIS，直接产出 `墨枢-0.3.0-setup.exe`；项目另打一个 `全民求生-极点-项目包.zip`，首次打开时手动选目录。

- 适合：把应用分发给多人、需要开始菜单/卸载入口。
- 优点：安装体验标准，安装目录可选。
- 缺点：两个产物，项目仍要手动导入；要做到“装完自动带书”，需要改主进程首启逻辑（把内置项目复制到文档目录并登记），本期不做。

**结论：本次迁移用方案 A；方案 B 作为后续分发形态保留。**

## 6. 构建与打包步骤

### 6.1 构建应用

```powershell
cd F:\MoShu
npx tsc -p tsconfig.json --noEmit
npx vite build
npx electron-builder --win dir --config.asar=false --config.win.signAndEditExecutable=false --config.npmRebuild=false --publish never
```

产物：`F:\MoShu\release\0.3.0\win-unpacked\`。

三个参数的原因：

- `--config.asar=false`：pnpm 把 `@lancedb/lancedb-win32-x64-msvc` 放在 `.pnpm` 目录，electron-builder 能打进 asar，但不会把里面的 `.node` 解包，运行时会加载失败。关闭 asar 后原生模块按真实路径加载。
- `--config.win.signAndEditExecutable=false`：本机没有符号链接权限，`winCodeSign` 解压会报 `Cannot create symbolic link`；同时跳过 rcedit，避免卡在 exe 元数据写入。代价是 exe 图标与版本信息为 Electron 默认值，窗口图标仍由 `build/icon.png` 提供。
- `--config.npmRebuild=false`：首次构建已经完成 `better-sqlite3` 的 Electron 41 重编译，避免重复重建。

> 需要安装包时改用 `npx electron-builder --win nsis portable --config.asar=false ...`，产出
> `墨枢-0.3.0-setup.exe` 与 `墨枢-0.3.0-portable.exe`；本次迁移包不使用这两个文件。

### 6.2 组包

```powershell
$ver   = "0.3.0"
$date  = "20261111"
$name  = "墨枢-$ver-迁移包-$date"
$out   = "F:\MoShu\release\migration\$name"

New-Item -ItemType Directory -Force -Path $out | Out-Null
Copy-Item "F:\MoShu\release\$ver\win-unpacked" "$out\墨枢" -Recurse
Copy-Item "F:\MSnovel\全民区块求生" "$out\项目\全民区块求生" -Recurse
Copy-Item "F:\MoShu\docs\新书-墟星" "$out\文档\新书-墟星" -Recurse

# 清理禁止项
Remove-Item "$out\项目\全民区块求生\.moshu\archive-*" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item "$out\项目\全民区块求生\.moshu\*.bak-*" -Force -ErrorAction SilentlyContinue
Remove-Item "$out\项目\全民区块求生\.moshu\moshu.db-wal","$out\项目\全民区块求生\.moshu\moshu.db-shm" -Force -ErrorAction SilentlyContinue
```

## 9. 风险与规避

| 风险 | 表现 | 规避 |
|---|---|---|
| 未签名 | SmartScreen「Windows 已保护你的电脑」 | 说明里写：更多信息 → 仍要运行；或对 ZIP 做 SHA256 校验 |
| 原生模块 ABI | 启动报 `NODE_MODULE_VERSION` 不匹配 | 必须用本机构建的 `win-unpacked` 整目录，不要替换 `resources\app\node_modules` |
| winCodeSign 解压失败 | `Cannot create symbolic link`，构建中断 | 加 `--config.win.signAndEditExecutable=false`，或开启 Windows 开发者模式后重试 |
| rcedit 卡住 | 构建停在 `updating asar integrity executable resource` | 同上跳过 exe 元数据写入；窗口图标不受影响 |
| lancedb 缺原生包 | 启动即崩，日志提示找不到 `lancedb.win32-x64-msvc.node` | 保持 `asar=false`，并确认 `resources\app\node_modules\@lancedb\lancedb-win32-x64-msvc` 存在 |
| 中文路径 / 空格 | 极少数原生模块读路径异常 | 解压目录用短路径，例 `D:\MoShu-Pack\` |
| 文件锁 | 打包后数据库缺 WAL 数据 | 打包前退出应用并 checkpoint |
| 误开旧库 | 章节回到改造前 | 不打包 `archive-*`、`*.bak-*` |
| 跨平台复制 | LanceDB 报找不到二进制 | 只复制 win32 构建产物，不跨 macOS/Linux |
| 体积过大 | ZIP 超 300 MB | 用 7-Zip `-mx=7`；必要时剔除 `locales` 中未用语言 |
| API Key 泄露 | 包里带出密钥 | 永不打包 `~/.moshu/models.json`；ZIP 不加密时只走私有存储 |
| 项目登记路径失效 | 首页卡片显示缺失 | 用 `导入项目登记.ps1` 重写 `projects.json`，或手动打开一次项目 |
